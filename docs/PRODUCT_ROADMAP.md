# Notch Calendar 产品路线

## 产品定位

Notch Calendar 是一个安静、本地优先的个人工作台。它利用刘海提供一眼可读的日程，
利用桌面窗口承载需要主动打开的工作与信息，但绝不以弹窗、抢焦点或高频通知换取存在感。

所有新增能力都遵守四条发布原则：

1. 只有用户明确打开页面时才联网或显示大窗口。
2. 网络、权限和第三方服务失败时保留旧内容，并给出可执行的非空状态。
3. 展示外部数据时始终注明来源、更新时间和实时性，不伪装成投资建议。
4. 日历、便笺和专注数据默认只留在本机；任何上传能力都必须单独说明并由用户开启。

## 已落地：安静模式与情报台

- 被动启动只初始化刘海服务，不主动激活桌面窗口。
- 刘海需要指针停稳后才展开；会议状态导致的两侧伸展改为默认关闭的选项。
- 桌面小组件使用明确的打开入口，避免整张组件误触后拉起应用。
- 情报台提供 Hacker News 热门、Ask 和 Show 三类信号，每类只显示十条。
- 情报台仅在打开页面时刷新，使用短超时、有限并发和 30 分钟本地缓存；断网时继续显示上次结果。

## 下一阶段候选

### 1. 自选行情

目标不是复制交易软件，而是在工作台里回答“今天我关注的市场发生了什么”。

计划范围：

- 最多 8 个指数、股票、ETF 或加密资产；支持分组与拖拽排序。
- 正规数据提供方适配层，首个实现优先选择有公开文档和明确展示许可的服务。
- 用户自己的 API Key 只存入 macOS Keychain，不写入偏好、日志或同步文件。
- 15 分钟缓存，默认仅手动刷新；收到限流后停止自动尝试。
- 每条行情显示数据源、交易所、时间及“实时 / 延迟 / 收盘”状态。
- 不进入刘海浮层，不提供价格弹窗，不默认开启提醒，不输出买卖建议。

发布门槛：在没有稳定数据许可、Keychain 存储、限流降级和固定响应测试之前，
不接入 Yahoo、东方财富、腾讯等未承诺第三方稳定性的私有接口。

### 2. 情境天气

- 用户手动选择城市，不申请定位权限，也不读取或上传日程地点。
- Today 页面显示当前天气、当天降水窗口，以及下一项日程开始时的天气。
- 数据保留更新时间和离线缓存；天气服务不可用不影响日历页面。

### 3. 本地咨询助手

- 将便笺整理成下一步、决策利弊、会前检查单或复盘问题。
- 优先使用系统本地模型；模型不可用时保留现有便笺，不出现不可操作的空白页。
- 每次处理前展示输入范围，不把日历或便笺静默发送到云端。
- 继续支持 macOS 15 基础功能；新系统能力只做渐进增强。

### 4. 日程情报摘要

- 把今天的空闲时段、即将开始的会议和情报台收藏组合成一页晨间简报。
- 摘要只在用户打开时生成，不在后台定时弹出。
- 支持“稍后看”和本地归档，不引入社交信息流或无限滚动。

### 5. 专注与恢复

- 根据下一场会议自动推荐不会冲突的专注时长，但不自动启动计时。
- 增加短休息引导、今日完成记录和可导出的周回顾。
- 所有提醒均为显式开启，并提供一键静音和勿扰时段。

## 稳定性长期门槛

- 窗口呈现、深链和悬停必须有纯逻辑测试与实际前台应用不变的冒烟测试。
- 外部数据客户端必须覆盖超时、断网、HTTP 错误、部分响应、畸形响应、超大响应和旧缓存降级。
- 后台刷新必须事件驱动或有明确 TTL，不允许秒级轮询第三方接口。
- Release 必须通过 Debug/Release 构建、全部测试、签名结构、DMG 挂载、版本一致性和双架构检查。
- 正式 1.0 还要求 Developer ID 签名与 Apple 公证；在凭据就绪前，发布包必须明确属于手动安装渠道。
