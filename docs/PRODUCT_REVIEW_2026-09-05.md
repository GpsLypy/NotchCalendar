# Notch Calendar：从功能集合走向专业工具

审视日期：2026-09-05。范围仅为功能和实用性；本轮不加入支付、账号、订阅或功能授权门槛。文中的“事实”来自当前代码、README 和第一方产品资料；“判断”是产品建议，不代表已验证的市场需求。

## 1. 当前基础与主要缺口

**事实：v0.6 基线**已有刘海日历、Today、桌面月历、智能入会、专注计时、自动保存便笺，以及 Radar、行情、讨论、简报和三个桌面小组件。静默启动、主动展开、本地保存、网络失败保留缓存、数据来源和更新时间提示，已经体现出对日常使用的考虑。计时支持休眠恢复，更新提供完整进度与校验，这些都是应保留的基础。

**事实：本轮开发前**，日历默认读取全部来源，用户无法排除私人日历、订阅节假日或重复账户；专注只有固定时长和累计次数；便笺是一段独立文本。日程、专注与记录之间缺少连接。资讯页面虽丰富，却不能替代这些基础能力。

**判断：**现阶段最值得做深的承诺是“帮我安排今天，进入专注，顺利参加会议，并找回自己的记录”。刘海是便捷入口；真正的价值来自每天重复使用时减少操作和遗漏。任何单个功能都容易复制，可靠的完整流程、持续兼容和使用习惯才可能逐渐形成优势。

## 3. 本轮开发范围

本轮已实现三个相互连接、无需外部服务的小切片，纳入 0.7.0：

1. **统一日历来源。** 选择哪些日历参与 Today、刘海、月历、小组件和时间安排；保存选择，并区分无权限、无日历、全部隐藏。
2. **今日时间安排。** 在可配置工作时间内计算剩余空档，扣除会议前后缓冲，显示真实重叠日程；为当前空档准备合适的专注时长，由用户明确开始。
3. **专注记录。** 5–180 分钟自定义专注、单独的休息类型、今日/本周已完成分钟、最近 1,000 条本地完成历史和 CSV 导出。旧累计次数保留，完成记录与计时停止状态一起保存，避免重启后重复记录。

边界同样明确：全天事件保留在日程中，但不占用本轮空档计算；推荐取决于所选日历和当时数据，不等于预约或自动避让。计时器只记录计时会话，不测量人在电脑前的真实工作量。旧累计次数不能编造成历史记录。

本轮没有实现会议提醒／延后、任务标签、会议笔记关联、全量数据备份恢复或 Shortcuts。这些应保留为后续候选，不作为当前卖点。

## 4. 专业软件的功能底线与优先级

**P0：数据可信、状态明确。** 各入口使用同一来源规则；撤销权限或移除账户后清理过期内容；空档不重叠、不越界。计时重启和休眠后保持一致，完成只记一次；写入或导出失败应给出可执行说明。

**P1：完成每日工作闭环。** 显式开启的会议提醒、稍后提醒和单次静音；快速入会与复制链接；按事件关联的本地记录。随后补充便笺和配置导出／恢复，让用户能搬家、找回内容。全局快捷键应可修改，并清楚反馈冲突。

**P2：提高熟练用户效率。** Shortcuts、跨时区查看、可配置工作日、专注任务标签与周回顾。扩展前先观察使用反馈，避免把统计做成必须维护的负担。

**判断：**近期降低新增资讯模块的优先级，保留现有功能并考虑自主隐藏。无需复制整套系统 HUD 或增加通用 AI 对话；优先让日历、专注和记录之间少一次切换。

## 5. 验收尺度

- **来源一致：** 隐藏一个日历后，各入口同步变化；全部隐藏、权限撤销、账户消失和重新授权都有正确结果，重新启动保留选择。
- **时间正确：** 覆盖跨午夜、夏令时、会议相邻／嵌套／重叠、全天与非忙碌事件、工作时间结束。缓冲只影响空档，不能制造冲突；点击时重新计算建议。
- **操作可预期：** 推荐不会覆盖进行中或暂停中的会话；准备时长与开始计时含义明确。键盘、窄窗口和中英文长文本都能完成主要动作。
- **记录可靠：** 暂停、恢复、重启、休眠与到期不会重复计数；CSV 日期、时长、记录数量与页面一致，导出失败可恢复。
- **发布可使用：** 构建与测试之外，还需真实权限、跨屏／无刘海、休眠唤醒和导出文件的手动检查。通过后再描述为已验证功能。

## 6. 本轮验证记录

首次验证日期：2026-09-05。以下记录为功能开发完成时的本地验证；后续 0.7.0 打包与发布准备见 [版本验收报告](VALIDATION_V0.7.0.md)，公开产物见 [v0.7.0 Release](https://github.com/GpsLypy/NotchCalendar/releases/tag/v0.7.0)。未引入收费功能。

- **完整测试：** 145 项测试，142 项通过、3 项按开关跳过、0 失败。跳过项分别为实时简报服务、旧营销截图以及本轮离屏渲染。
- **额外界面验证：** 随后单独启用本轮离屏渲染测试并通过。检查了 647 / 980 点宽的中文和英文时间规划、专注界面，以及全隐藏状态和日历来源设置；共 10 张原生 SwiftUI 图像。使用合成日历、独立偏好设置和模拟日历提供方，不访问真实日历。图像位于 `.build/planning-review/`。
- **构建：** Debug 构建通过；Release 的 arm64 与 x86_64 构建通过，并检查主程序、更新器和小组件的 universal2 架构。
- **功能边界：** 新增 26 项逻辑/持久化测试覆盖来源筛选、全隐藏短路、权限撤销、前后日缓冲、重叠与相邻事件、夏令时、建议过期、旧计时迁移、立即暂停保护、重启完成一次、跨日/周统计、历史上限、CSV 实际读写及失败。格式检查通过。
- **仍需实际设备验收：** 真实 iCloud/Google/Exchange 账户的来源切换与权限重新授权、系统保存面板的完整点击操作、实体 Mac 休眠与跨屏切换。已有纯逻辑测试与离屏渲染不等同于完成这些手动验收。

日历仍为只读；时间建议只用于准备计时器，不会写入或调整系统日程。完成时长按结束当天计入；计时器运行期间的睡眠也会经过计时时间，不应把该数字视为实际劳动量。发布采用既有手动安装渠道。
