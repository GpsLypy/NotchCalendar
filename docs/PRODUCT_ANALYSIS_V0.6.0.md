# Notch Calendar 0.6.0 产品解析与设计

## 产品真正解决的问题

Notch Calendar 的中心是「下一步要做什么」。刘海负责抬眼可见的日程，桌面窗口承载需要主动阅读的内容。Today、Calendar、Focus、Scratchpad、Radar 已经形成从安排到执行、记录和发现的路径。它的独特价值是短路径与安静的存在感；窗口多少或信息量大小本身不是优势。

现有缺口有三处。Radar 只有十条标题，看见信息后缺少深入讨论的空间；信息来自单一社区，热度不能代替一手来源；用户的市场关注与工作台分离，需要反复切换网站。三个新功能分别补齐「市场发生了什么」「别人怎样理解」「源头到底说了什么」。

## 本版的三个完整功能

| 功能 | 用户任务 | 完成标准 | 边界 |
| --- | --- | --- | --- |
| 自选行情 | 查看自己关注的美股或 ETF 收盘变化 | 添加/删除/排序，凭据配置，手动刷新，价格/涨跌/交易日，离线留存 | 最多 8 项，个人 API Key，非实时行情；不做买卖推荐 |
| 舆论室 | 阅读真实讨论，形成自己的判断 | 选话题、读署名评论、打开原帖、保存私人立场和笔记 | HN 社区有限样本；自己的观点只存本机，不冒充全网民意 |
| 信息差简报 | 越过转述，读公开一手资讯 | 选择来源、关键词筛选、打开原文、收藏与已读、本地缓存 | 明确来源与时间，不暗示内部消息，不生成虚构事实摘要 |

## 创意如何落到体验

这里的“好玩”来自探索与反馈，而不是无穷刷新。行情是有限的个人观察台；舆论室把社区表达和自己的立场放在同一个阅读现场；简报让收藏和已读逐渐形成个人信息档案。用户看完可以回到专注计时，信息阅读有出口。

保留 Radar 作为快速扫读；另外三项与它同级，直接进入，快捷键分别为 ⌘6、⌘7、⌘8。侧栏导航可滚动，保证 860 × 520 的最小主窗口仍能访问所有入口。

## 视觉方案

- 石墨画布 #070708、侧栏 #0D0D10、抬升面板 #131316、珊瑚主色 #F43B5B、成功色 #66D694、正文接近白色。
- SF Pro / 系统中文字体承载正文和标题，SF Mono / 等宽数字承载价格和时间，沿用原生 macOS 的可读性。
- 行情以交易日和抓取时间区分数据含义；舆论室用署名评论串组织内容；简报强调来源、标题和阅读状态。
- 不新增无意义动画。保留系统“减少动态效果”，标签和正负号共同表达状态，不能只靠颜色判断。

最初把三页都设计成同样的统计卡片会抹掉阅读差异，因此改为以各自内容的结构区分页面。品牌表达集中在珊瑚色与信息排版，刘海本身不增加行情滚动条或新闻弹窗。

## 稳定性与隐私要求

仅打开信息页或手动刷新才请求相应来源。请求有超时、大小限制、并发上限和取消机制；失败时保留旧内容，明确标注缓存，不把刷新时间当作行情交易时间。损坏缓存可重新获取，收藏与私人笔记不能因请求失败丢失。

日历、随手记和专注记录不发送给资讯服务。行情凭据只进入系统钥匙串。真实外部来源、个人理解和演示素材分别标注。
