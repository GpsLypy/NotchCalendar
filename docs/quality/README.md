# 质量验收与发布记录

当前迭代为 1.2.0（build 26）。[本版验收记录](1.2.0.json) 与 [1.2 发布及验证说明](RELEASE_1.2.0.md) 分别记录机器可读状态和人工可审阅的结果。最终性能与部分实机验收仍为 **pending**；发布决定不把待验收改为通过。发行包只保留运行必需的 ad-hoc，不使用 Developer ID 证书或 Apple 公证。

## 1.1 的验收重点

- 石墨色工作台与独立桌面月历：检查窗口大小变化、月份与选中日期、长标题和空日程布局，避免紧凑刘海视图直接铺在大窗口中。
- 启动默认日历收缩态，主窗口不自行展开；主动打开工作台时默认进入日历，明确指定页面的入口仍按目标打开。
- 恢复的 49:20 暂停专注不占据刘海，任务、剩余时间和历史仍在；本次主动开始或恢复后显示专注，同次暂停保留控制入口。
- 恢复的运行中专注在后台继续并只完成一次，日历默认入口不影响计时；启用的有效会议仍按统一优先规则切换。
- 页面隐藏后取消周期刷新；刘海收起内容共用一个时钟，静置按分钟和会议边界更新，独立结束时刻负责专注完成。

自动化检查与实机检查分别记录，不能相互替代。新功能继续遵循 [统一活动规范](ACTIVITY_CONTRACT.md)。本次没有扩展活动种类。

## 性能采样方法

构建优化后的独立 macOS 探针，使用产品的刘海控制器、SwiftUI 视图、专注模型和隐藏主窗口。探针使用一次性配置与合成日历，不请求真实日历权限，不发送通知、不打开会议网址，也不刷新个人小组件。

每种状态预热 3 秒，连续采样至少 30 秒，重复两轮。CPU 按单逻辑核心 100% 计算；Mach 时间先换算为纳秒。分别记录 interrupt wakeups 与 package-idle wakeups，不把它们混成一个能耗数值。

| 状态 | 平均 CPU | CPU p95 | interrupt wakeups |
| --- | --- | --- | --- |
| 静置 | ≤ 0.5% | ≤ 2% | ≤ 1 次/秒 |
| 专注运行 | ≤ 2% | ≤ 5% | ≤ 5 次/秒 |
| 会议切换 | ≤ 3% | ≤ 8% | ≤ 10 次/秒 |

预算在采样前固定。采样时临时保持显示器开启，结束后释放电源断言；手动锁屏仍有效。窗口不可见、遮挡、面板展开或鼠标输入都会使样本无效。检测到系统锁屏标记立即拒绝采样，不能仅凭 AppKit 的窗口可见性判定解锁；系统未提供标记时保留 unknown，并要求人工确认。

真实 EventKit 账户同步、网络和独立 WidgetKit 进程不包含在这份隔离采样内。保留原始数据及排除原因，不能把旧样本复制为本版通过结果，也不能通过放宽阈值或丢弃有效的失败样本通过验收。

```sh
python3 Scripts/quality/build_probe.py
python3 Scripts/quality/measure.py .build/quality-1.1-unique --repeats 2
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer swift test
python3 -m unittest discover -s Scripts/quality -p 'test_*.py'
python3 Scripts/quality/verify_release_gate.py 1.2.0 --strict
```

开始采样前确认屏幕解锁、刘海可见，采样时不操作鼠标与窗口；输出目录必须为新目录。原生交互测试另以 `NOTCH_DESK_INTERACTION=1` 显式开启，它不替代实际悬停、显示器插拔或休眠测试。

## 补齐硬件证据

在内置刘海屏和普通外接显示器上分别验证：快速经过不展开、停留约 350 ms 展开、移出收起；点击模式、活动切换与键盘操作；展开时休眠/唤醒、拔插显示器和改变主屏后的定位与焦点恢复。

每项记录设备类别、实际行为、运行代码指纹及证据路径。源码指纹只忽略单独核验的版本号与构建号；其余运行代码、资源或配置变化均使旧证据失效。不得把没有设备的项目标为通过。

## 发布门槛和逐版本例外

打包脚本和 GitHub Actions 默认检查 `docs/quality/<版本>.json`。缺少证据、错误版本、运行代码不匹配、输入干扰、锁屏或实测超预算均阻止正常通过。

所有者明确要求在已披露待验收的情况下发布时，只能记录一次适用于本版本和最终运行代码的例外。记录必须包含相互匹配的原始所有者请求、版本、指纹和**完全一致**的待验收列表；记录缺失、请求不符、新增缺口或源码变化都会使例外无效。旧版本例外不会自动继承。实测硬件失败、无效性能样本或超预算不能被该例外覆盖。

`--strict` 始终输出全部待验收项并返回未通过。命中有效的本版发布例外时，普通打包检查明确输出“已授权带待验收项发布”及逐项列表，不输出“质量门槛通过”。[1.0 的历史记录](1.0.0.json)、[1.1 的记录](1.1.2.json) 与 [1.2 的记录](1.2.0.json) 独立保存。
