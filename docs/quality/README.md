# 1.0 质量验收

1.0.0 按项目所有者在获知待验收项后提出的最新指示发布。验收状态仍为 pending，不宣称全部门槛通过；[验收记录](1.0.0.json) 单独保存仅适用于 1.0.0 当前运行代码指纹的发布例外。仅保留运行必需的 ad-hoc，不使用 Developer ID 或 Apple 公证。

## 已落实的约束

- 隐藏主窗口不构建页面树，停止随每秒专注刷新重绘日历和时间轴。
- 收起态活动共用一个时钟；静置时按整分钟及下一场会议边界刷新，运行中的可见倒计时每秒刷新。
- 收起态的小型会议进度环按秒直接更新，避免每秒触发持续一秒的逐帧动画；展开态保留原有动效。
- 专注完成使用独立的一次性结束时刻，不依赖窗口可见；暂停取消这个结束任务，恢复和唤醒后重新对齐。
- 刘海增加 Command-1/2 活动切换、Space 专注控制、Escape 关闭。睡眠和唤醒通知会清除过期悬停、收起面板并释放键盘焦点。
- 后续活动遵循 [统一活动规范](ACTIVITY_CONTRACT.md)，新增活动种类在门槛通过前暂停。
- 发布脚本和 GitHub Actions 都检查 [1.0 验收记录](1.0.0.json)。默认情况下，缺硬件证据、遮挡/输入干扰、超预算或源码指纹不符都会阻止正式版本发布。1.0.0 的一次性例外仅覆盖记录中列出的待验收项；新的缺口、实测超预算或运行代码变化仍会阻止发布。

## 性能采样方法

构建运行优化后的独立 macOS 应用，使用与产品相同的刘海控制器、SwiftUI 视图、专注模型和隐藏主窗口。不会请求真实日历权限，也不会发送通知、打开会议网址或刷新用户的小组件。

每种状态预热 3 秒，连续采样至少 30 秒，重复两轮。CPU 按单逻辑核心 100% 计算；Mach 时间先换算为纳秒。分别记录 interrupt wakeups 与 package-idle wakeups，不将它们混成一个“能耗”数值。

采样时临时保持显示器开启，结束后释放电源断言；手动锁屏仍然有效。窗口不可见、采样中遮挡、展开面板或鼠标输入均使样本无效。单独读取系统会话锁定标记：检测到锁屏立即拒绝采样，不能仅凭 AppKit 的窗口可见性判定解锁。系统未提供锁定标记时保留 unknown，仍需人工确认显示状态。真实 EventKit 账户同步、网络及独立 WidgetKit 进程不包含在这份隔离采样内。

早期试测保留为 `performance-reference-pre-gate.json`，**不用于验收**：当时没有明确开启默认关闭的会议状态，也未持续检测窗口可见性。最终结果以单独的 `performance-verified-2026-09-06.json` 为准，当前该记录为 **pending**，没有把旧样本移作最终构建的通过证据。

明确开启会议状态后，两轮会议切换参考值为平均 CPU 3.75–3.93%、p95 11.44–11.90%、interrupt wakeups 38.09–38.19 次/秒，超过原定预算。已据此移除收起态进度环的持续动画；修复后的采样在锁屏预检被拒绝，需解锁后复测。[修复前原始样本](evidence/performance-before-ring-fix.json) 缺少每秒系统锁定标记，仅供定位问题，不作为前台性能通过证据。

最终源码自动化结果：227 项 Swift 测试中 222 项通过、5 项既有可选测试跳过、0 失败；该轮 9 项发布门槛与 CPU 计量校验通过。1.0 发布时新增例外边界测试后共 12 项通过；标准 Swift 回归为 218 项通过、9 项可选测试跳过，见[发布验证](../VALIDATION_V1.0.0.md)。主程序、更新器、小组件均已构建 arm64 + x86_64。纯模拟唤醒测试不能替代实际休眠。

### 重现

```sh
python3 Scripts/quality/build_probe.py
python3 Scripts/quality/measure.py .build/quality-run-unique --repeats 2
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer NOTCH_DESK_INTERACTION=1 swift test
python3 -m unittest discover -s Scripts/quality -p 'test_*.py'
python3 Scripts/quality/verify_release_gate.py 1.0.0 --strict
```

先确认屏幕解锁、刘海可见，采样期间不要移动鼠标或操作窗口。输出目录必须是新目录，避免覆盖证据。若有输入干扰，应保留该样本，并另行补测；有效样本超预算不能靠修改阈值或丢弃样本通过。

### 补齐硬件验收

连接真实普通显示器后，在内置和外接屏分别完成：短暂经过不展开、停留约 350 ms 展开、移出收起；点击模式、活动切换、键盘操作；展开时合盖/唤醒、拔插外接屏和改变主屏后位置与焦点恢复。应记录设备、源码指纹、具体结果及证据；源码指纹仅忽略单独校验的版本号与构建号，其余运行代码、资源与配置变化会使证据失效。只在实际完成后更新验收记录，不能仅将 `pending` 改为 `passed`。

严格检查仍会返回未通过。打包使用同一检查器，若命中已记录的 1.0.0 发布例外，会明确打印待验收列表，而不会输出“质量门槛通过”。后续版本不继承这个例外。
